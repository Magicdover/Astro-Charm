用久了几门编程语言，会慢慢觉得它们各有「性格」。语法背后，其实藏着一套关于「该信任程序员多少」「为谁牺牲什么」的哲学。聊聊几门主流语言的脾气。

## C：给你全部自由，也给你全部责任

C 语言像一把没有护手的利刃。它几乎不拦着你，直接让你操作内存，因此极快、极灵活，也极容易割到手。

```c
int *p = malloc(sizeof(int) * 10);
// 忘了 free(p)，就是一次内存泄漏
```

:::note[它的信条]
相信程序员，不做多余的保护。半个多世纪过去，操作系统与数据库的底层，依然是它的天下。
:::

## Python：让人读起来舒服

如果说 C 为机器着想，Python 则为**人**着想。它语法干净、贴近自然语言，把复杂藏在背后，让你专注于「做什么」而非「怎么做」。

```python
squares = [x * x for x in range(10)]
```

代价是运行慢一些。但在数据科学、AI、脚本这些「开发效率优先」的场景，它几乎成了默认选项。

## Rust：又要快，又要安全

长期以来，「运行快」和「不出内存错误」像鱼与熊掌。Rust 想同时都要——它用一套**所有权**（Ownership）机制，在编译期就堵死了大量内存 bug，且几乎不牺牲性能。

:::warning[有代价的优雅]
代价是陡峭的学习曲线。你得先说服那个严格的编译器，它才让你的程序跑起来；但一旦通过，你会对它的安全颇有信心。
:::

## 没有最好，只有最合适

语言之争常常热闹，但选语言更像**选工具**：写操作系统、拧螺丝、盖房子，本就该用不同的家伙。理解每门语言在为谁、牺牲什么，比争论谁更强，有用得多。

:::tip[一句话收尾]
语言塑造思维。多学一门风格迥异的语言，收获的往往不是又一种语法，而是又一种看待问题的角度。
:::
